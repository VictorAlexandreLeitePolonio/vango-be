# Cycle 0 — Local Supabase Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set up a reproducible, version-controlled, and testable local Supabase development environment without creating VanGo domain entities or routes yet.

**Architecture:** Cycle 0 uses the Supabase CLI and Docker to generate the official project structure. The only custom migration creates a private schema to host internal helpers in subsequent cycles; the remote project remains untouched.

**Tech Stack:** Supabase CLI, Docker, PostgreSQL, pgTAP, and SQL migrations.

**Spec:** `be-tech-plan.md`, sections 3.1, 3.3, 11, 12, 13; `CONTRIBUTING.md`, sections 2, 3, 4, 5, 12, 13.

## Global Constraints

- Do not add a Node.js server, parallel auth layer, custom JWT, or custom Socket.io server.
- Do not create domain entities, RPCs, Edge Functions, Cron jobs, buckets, or business RLS policies in this cycle.
- Work locally before applying any changes to remote projects.
- Create migrations via `supabase migration new`; do not invent timestamp prefixes manually.
- Do not use the MCP `apply_migration` to iterate on the local database.
- Do not install Node dependencies or create `package.json` inside the repository.
- Do not expose the local stack to the internet; it uses local development credentials.
- Do not commit secrets, remote keys, or credentials to Git.
- Do not commit or push without explicit authorization.
- Update `deliverables.md` strictly with verified execution results.
- Execute the `software-quality-gate` skill before declaring the cycle completed.

## Cycle Scope

### Included

- Supabase CLI installation outside repository.
- Initialization of the official `supabase/` structure.
- Running the local stack via Docker.
- Migration to create and restrict access to `private` schema.
- Minimal pgTAP environment test.
- `seed.sql` with zero domain records.
- Status updates in README and deliverables log.

### Excluded

- `profiles`, `fleets`, memberships, roles, or audit logs.
- Domain Data API tables or RPC functions.
- Realtime, Storage, Edge Functions, or Cron jobs.
- Marketplace, vans, routes, daily trips, push notifications, or map tracking.
- Migrations applied to remote projects.

### Task 3: Create Initial Failing (RED) Environment Test

**Files:**

- Create: `supabase/tests/database/000_environment.test.sql`.

- [x] **Step 1: Create pgTAP test**

Create `supabase/tests/database/000_environment.test.sql`:

```sql
begin;

create extension if not exists pgtap with schema extensions;

select plan(3);

select has_schema(
  'private',
  'private schema exists'
);

select ok(
  not has_schema_privilege('anon', 'private', 'usage'),
  'anon cannot use private schema'
);

select ok(
  not has_schema_privilege('authenticated', 'private', 'usage'),
  'authenticated cannot use private schema'
);

select * from finish();

rollback;
```

- [x] **Step 2: Run test and confirm RED failure**

Run:

```bash
supabase test db supabase/tests/database/000_environment.test.sql
```

Expected: FAIL because `private` schema does not exist yet.
